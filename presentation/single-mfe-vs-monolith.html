MFE-архитектура сама по себе быстрее монолита — при загрузке одного модуля браузер получает только нужный код (57 KB vs 174 KB скриптов).


Деградация возникает при загрузке нескольких MFE — каждый дополнительный модуль добавляет домен, remoteEntry.js, loadShare() и набор чанков. При 3 MFE: 35 скриптов с 5 доменов порождают каскад JS Parse/Compile, который убивает TTI и Performance Score.

Рекомендация

  1. Минимизировать число MFE на страницу — идеально 1 модуль + shell

  2. Lazy-load remote MFE — не загружать remoteEntry.js до навигации к модулю

  3. Объединять мелкие MFE — если модули всегда загружаются вместе, они должны быть одним MFE

  4. Preload hints — для критических чанков текущей страницы, чтобы снизить каскад запросов
